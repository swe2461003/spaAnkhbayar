# Excel болон сайтын холболт

GitHub Pages нь frontend танилцуулгыг харуулна. Байнгын хадгалалт, имэйл ба нууц үгийн нэвтрэлт, компьютер дээрх Excel файлтай хоёр чиглэлийн синкэд Node.js сервер ашиглана.

## Нэг файлтай эхний хувилбар

1. Node.js 24 буюу түүнээс шинэ хувилбар суулгана.
2. `npm ci` ажиллуулна.
3. `.env.example`-ийг `.env` гэж хуулна.
4. `WORKLOAD_FILE=C:/.../B-Tsagiin-Tootsoo.xlsx` гэж үндсэн файлын бүтэн замыг тохируулна. Нууц үг болон өгөгдлийг GitHub-д оруулахгүй.
5. `npm run start:server` ажиллуулж `http://localhost:4175/#/workload` хаягаар орно.
6. Анхны админы нэр, имэйл, 12-оос доошгүй тэмдэгттэй нууц үгийг серверийн компьютер дээр нэг удаа үүсгэнэ.

Өгсөн Word файлыг эхлээд Excel болгон хөрвүүлсэн. Эх Word файл өөрчлөгдөхгүй. Энэ хөрвүүлсэн үндсэн Excel дээр цааш ажиллана. Нэг workbook, нэг багшийн мэдээллийг эхний ээлжид холбоно.

## Хэрэглэх

- Excel-ийн `Workload` хуудсанд `unitHours` болон `quantity` утгыг засаад **Save** хийнэ. Сервер 5 секунд тутам өөрчлөлтийг шалгана.
- Сайтын **Багшийн В цаг** хэсэгт **Засах → Хадгалах** сонгоно. Өөрчлөлтийг SQLite-д хадгалж, Excel рүү бичнэ.
- `quantity` хоосон бол гүйцэтгэл бөглөөгүй гэсэн утгатай; 0 бол бодит тэг. `total` нь формулаар бодогдоно.
- Сайтын хүснэгт 4 секунд тутам шинэчлэгдэнэ. Засварлаж байгаа мөрийг автоматаар солихгүй.
- Excel өөр программд файлыг түгжсэн бол **Save** хийгээд хаана. Сервер дараагийн шалгалтаар бичихийг оролдоно. Алдааг сайтад харуулна.
- Татсан өөр хуулбарыг биш, сайтад заасан үндсэн Excel файлыг засна.
- Хоёр талын утга зэрэг өөрчлөгдвөл зөрчил харуулна. Админ хувилбаруудыг харьцуулж аль утгыг хадгалахаа сонгоно. Excel-ээс мөр алга болсныг автоматаар устгал гэж үзэхгүй.
- Бичихээс өмнө Excel-ийн өмнөх хувилбарыг нөөцөлж, сүүлийн 20 хуулбарыг өгөгдлийн хавтаст хадгална.

Компьютер, сервер унтарсан үед синк ажиллахгүй. Excel-д Save хийгээгүй өөрчлөлтийг сервер уншихгүй. Хэд хэдэн хүн ашиглах онлайн хувилбар хэрэгтэй бол серверийг байнгын хадгалалттай, HTTPS хаягтай орчинд байршуулна. Интернетэд байрласан сервер хэрэглэгчийн компьютерийн файлыг шууд уншихгүй; тухайн тохиолдолд үүлэн файл эсвэл тусдаа локал холбогч хэрэгтэй.

## Хадгалалт

Серверийн `.data/lms.sqlite` дотор хэрэглэгч, нууц үгийн hash, session, өгөгдөл, аудит хадгалагдана. `LMS_DATA_DIR`-ээр замыг сольж болно. Өгөгдлийн хавтас, `.env`, Excel-ийн ажлын файлыг GitHub-д оруулахгүй. Серверийг зогсоосны дараа өгөгдлийн хавтас болон Excel файлыг хамтад нь нөөцөлнө.

## Шалгах

```sh
npm run check
npm test
```

Ажлын цагийн тест нь Excel → сайт, сайт → Excel, формулын хадгалсан үр дүн, хоосон ба тэг утга, зөрчил, давхардсан id, устсан мөрийг шалгана.

## Дараагийн боломжуудын суурь

Серверт таван эрх, тайлан, аудит, архивын API суурь бэлэн. Эхний хувилбарын цэсэнд зөвхөн одоогийн хуудас болон нэг файлтай **Багшийн В цаг** хэсгийг гаргасан. Магадлангийн албан ёсны тайлангийн шалгуур, байгууллагын бодит эрхийн хүрээг тусад нь тохируулна.

Байгууллагын Microsoft 365 account ашиглах бол `EXCEL_MODE=graph`, MS_CLIENT_ID, MS_TENANT_ID, MS_CLIENT_SECRET болон workbook-ийн Drive ID / Item ID-г тохируулж болно. Энэ нэмэлт Graph холболтыг бодит account дээр одоогоор баталгаажуулаагүй. Хувийн account-ийн эхний хувилбар локал XLSX синк ашиглана.
